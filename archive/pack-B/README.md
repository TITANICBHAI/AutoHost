# AutoHost
Android automation platform: a Kotlin host app that runs user automations — Python scripts, declarative flows, or an LLM agent loop (Phase 12) — with real device capabilities, per-task settings, profiles, schedules and recovery.

**Start with `HANDOFF.md`** (state, decisions, interfaces, what to write next), then `AGENTS.md` and `docs/PROGRESS.md`.

- `plan.md` — product plan and phases. `docs/` — layout, manifest, UI spec, gates, decisions, tracker.
- `sdk-python/` — Python SDK + fake-device simulator (unit-suite results: `docs/VALIDATION_REPORT.md`). Phases 1–8 Kotlin (`core/` incl. devapi, `runtime/`, `capabilities/` incl. ime/screen/projection/files/audio/net/notifications, `app/` — scheduling, triggers, reliability/observability/authoring loop, task UI + surfaces, Dev API + MCP), Phase 9 (`:capabilities:shell` — our own ADB client + transports + the shell tier), Phase 10 (`:capabilities:browser` — the visible WebView browser + a11y + CDP links with challenge-to-WAITING_USER routing; `:capabilities:vision` — OCR/template-match/QR with `hint:true` semantics; `:capabilities:data` — contacts/calendar/media, location/camera/mic/sensors, SMS/telephony with money rails; `net.socket`/`net.reverse` riders) and Phase 11 COMPLETE as written (part 1: `:runtime:js` — the JavaScript (QuickJS) runtime as the third runtime over the same broker; part 2: the capability-plugin host + `:plugin-sdk` + `samples/plugin-example`, app packs riding `config.packs` (ADR-080), the in-app Task Studio with the repo tab, `autohost ui web` inspector, the reverse-WS Dev API transport (`autohost bridge`), secret-free backup/restore, release signing + licence CI (`tools/licence_check.py`), `docs/USER_GUIDE.md` + `docs/OEM_MATRIX.md`, and the P11-12 port exercise) — written, unverified; Gate-10 behaviours are sim-proven in `samples/web-login-scrape` + `samples/ocr-demo`; Gate 11-b is **sim-proven** (python + flow + js coexist).
