## How to use this tracker
1. **Tick = done at the evidence level the item requires.** The default requirement is `UNIT`; override with `(needs: INTEG)` or `(needs: DEVICE)`; documentation and process items carry `(DOC)`. A tick needs an evidence line for every `[M]`/`[L]` item and every gate.
2. **Evidence ladder** (tag in parentheses after the id, highest wins): `(IMPORTED)` source staged verbatim, not integrated · `(WRITTEN)` code written or adapted, never built · `(COMPILED)` module builds · `(UNIT)` JVM/Python tests pass · `(INTEG)` in-process integration against the real broker/engine · `(DEVICE)` demonstrated on a real device (record device + API). `COMPILED` and above need an evidence line. **Importing or copying ARIA/ClosePaw code never counts as integration.**
3. **Ordering (ADR-084).** Phase order constrains *starting new implementation scope*, not verification ticks: tick each independently verified task as soon as it reaches its required level with evidence and its dependencies are ticked, whatever earlier device gates are open. A gate stays unticked until its own procedure and evidence exist. `--check` enforces evidence-on-tick and tracker consistency, not phase order; `{after: N}` on a phase header records that its implementation may start once the gates up to N have passed.
4. **Verification results are recorded the moment they exist:** command, exit status, key numbers, artifacts, environment on the item's evidence line. Pass → raise the ladder tag and tick if the required level is reached (a tick without a tag counts as the required level, default UNIT). Fail → keep the item unticked and add `(FAILING: reason)` with the command and error in the evidence line (`--check` rejects a failing item without evidence, or a ticked one).
5. **Dependencies:** `(deps: ID, ID)`; a task cannot be ticked before its dependencies; unknown ids and cycles fail `--check`.
6. **Flow markers:** `(WIP)`; `(BLOCKED: reason)` — every blocked item must be listed under **Blockers** (checked, so the two cannot disagree).
7. Sizes: `[S]` = 1 point, `[M]` = 2, `[L]` = 4; gates 2. Percentages are weighted by these points and **generated**: never type counts into prose; use `python3 tools/progress.py --stats`.
8. IDs are stable; never renumber. Add new tasks at the end of a phase with the next number.
9. After editing: `python3 tools/progress.py` then `python3 tools/progress.py --check` and `python3 tools/check_docs.py`; optionally `--html docs/progress.html`.
