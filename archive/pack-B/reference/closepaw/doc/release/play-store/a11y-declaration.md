# Accessibility Service Permissions Declaration

Source package: `ai.closepaw`

Actual service declaration note: the repository path is `app/src/main/res/xml/agent_accessibility_config.xml`, not `accessibility_service_config.xml`.

## Which feature uses Accessibility Service?

ClosePaw's natural-language phone operation feature uses Accessibility Service. The user gives ClosePaw a task in plain English, such as catching up on emails, comparing prices, or summarizing a thread, and ClosePaw reads the current app screen, plans the next step, and operates the visible UI on the user's behalf [doc/release/play-store/full-description.txt:3,8-11]. The declared Android service is `ai.closepaw.app.AgentService`, bound with `android.permission.BIND_ACCESSIBILITY_SERVICE` and the `@xml/agent_accessibility_config` metadata [app/src/main/AndroidManifest.xml:62-72]. The service configuration declares window state/content events, interactive-window retrieval, window-content retrieval, gesture capability, and screenshot capability [app/src/main/res/xml/agent_accessibility_config.xml:2-10]. Runtime screen observation is implemented by `AccessibilityPlatform.captureScreen()`, which reads the current foreground package, applies blocked-app masking, collects accessibility roots, and returns a structured screen snapshot [app/src/main/kotlin/ai/closepaw/platform/AccessibilityPlatform.kt:64-126]. Runtime operation is implemented by `AccessibilityPlatform.performAction()`, which maps the agent's requested UI action to click, tap, long-press, text entry, scroll, swipe, system-button, or wait handling [app/src/main/kotlin/ai/closepaw/platform/AccessibilityPlatform.kt:304-353].

## Why is it necessary?

Accessibility Service is necessary because ClosePaw is an assistive, voice-style replacement for manually tapping, swiping, reading, and typing through multiple Android apps. The user provides a high-level instruction, and the app must understand what is currently on screen before each action; `AgentTurnRunner` explicitly starts each turn by capturing a screen snapshot and foreground package before planning [app/src/main/kotlin/ai/closepaw/agent/AgentTurnRunner.kt:132-169]. The feature cannot be limited to ClosePaw's own UI, because the user's requested task may happen inside Gmail, Settings, a browser, shopping apps, or another foreground app; the product description states that the agent reads the screen, executes steps, and shows every tap and swipe through the Smart Capsule [doc/release/play-store/full-description.txt:8-11,16-20]. The service needs window content so it can identify visible controls [app/src/main/res/xml/agent_accessibility_config.xml:5,8], and it needs gesture/action capability so it can click, scroll, type text, swipe, and use system navigation when the user delegates phone operation [app/src/main/kotlin/ai/closepaw/platform/NodeActionPerformer.kt:22-40,113-141,182-249; app/src/main/kotlin/ai/closepaw/platform/AccessibilityGestureInjector.kt:37-79,82-101]. Without Accessibility, onboarding tells the user the automation feature cannot run [app/src/main/kotlin/ai/closepaw/ui/onboarding/OnboardingSteps.kt:811-819].

## User benefit + consent flow

ClosePaw benefits users who want to delegate phone operation instead of manually performing every step. It presents a prominent onboarding disclosure before requesting permission: "ClosePaw uses it to read the screen and perform taps so it can complete the tasks you ask for," and the expanded disclosure says it is active only when the user starts a task and that task screen content is sent to the chosen LLM provider for next-step selection [app/src/main/kotlin/ai/closepaw/ui/onboarding/OnboardingSteps.kt:810-819]. The user must press "Open Accessibility Settings" in onboarding [app/src/main/kotlin/ai/closepaw/ui/onboarding/OnboardingSteps.kt:114-140,811-817], after which the app launches Android's Accessibility Settings rather than enabling the service itself [app/src/main/kotlin/ai/closepaw/onboarding/OnboardingViewModel.kt:182-198; app/src/main/kotlin/ai/closepaw/app/MainActivity.kt:875-879; app/src/main/kotlin/ai/closepaw/app/MainActivityUiHelpers.kt:21-23]. The app then verifies the service connection after the user returns from Settings [app/src/main/kotlin/ai/closepaw/onboarding/OnboardingViewModel.kt:151-155,379-416; app/src/main/kotlin/ai/closepaw/onboarding/PermissionStateMonitor.kt:14-18]. During a task, the Smart Capsule exposes Takeover and Stop controls [app/src/main/kotlin/ai/closepaw/ui/overlay/model/CapsuleRenderSpec.kt:63-97,170-172], and the overlay controller wires those controls to session operations [app/src/main/kotlin/ai/closepaw/app/ServiceOverlayController.kt:84-93]. Takeover pauses the session at a safe point [app/src/main/kotlin/ai/closepaw/session/AgentSession.kt:504-530], and Stop routes to user-requested shutdown and cleanup [app/src/main/kotlin/ai/closepaw/app/AgentService.kt:175-185; app/src/main/kotlin/ai/closepaw/session/AgentSession.kt:593-659].
