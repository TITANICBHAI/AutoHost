## Architecture (what it does)
- Hand-written ReAct tool loop (AgentLoop.run): `while(true){ ensureActive; injectSteering; compactIfNeeded; route model; nextReply; record; if calls.isEmpty -> finish; for call: pipeline.execute; if Done -> finish }`.
  * NO run-level step/turn/time/token/cost cap in the loop (grep MAX_STEPS only hits run_steps batch=6). Termination = model calls `done`, or replies in prose, or provider failure, or user Stop, or approval expiry. => for unattended AutoHost runs hard budgets are mandatory (same gap as ClosePaw loop.md).
  * Empty-reply handling: retry x2 with 700ms*attempt delay on the GOOD model, then a nudge user message "Continue. Call a tool…"; then failure with a classified message by finish_reason (tool_calls/length/error).
  * tool_choice="auto" deliberately (not required) so the model can stop.
  * Steering: user text typed mid-run is drained at the next step boundary (`AgentSession.drainSteering`) and also forces the strong model for that step.
  * Plan mode: tool list is FILTERED to read-only set + propose_plan until approved ("enforced by the harness, not asked for in the prompt"). Reject/timeout => run ends, "Nothing was touched".
- Tool surface (small): ui_tree, screenshot, tap(node|x,y), swipe, type_text, press(back/home/recents/notifications), open_app, list_apps, wait(100..15000ms), skill, ask_user_question, todo_write, session_search, session_read, run_steps(<=6, batchable set), run_script(Lua), save_script, call_script, remember, forget, propose_plan, done, mcp__server__tool. Tool definitions "declared once and reused so a provider's cached tool prefix stays byte-identical" (prompt-cache friendly).
- ToolPipeline: describe -> blocked(screen off/locked) -> gate(Approvals) -> run under withTimeout (60 s local / 120 s MCP; blocking tools exempt) -> cap result 12,000 chars -> record ToolStarted/ToolFinished. Timeout is reported to the model, not fatal. Batch (run_steps) and Lua script sub-steps re-enter the SAME execute() at depth+1 (MAX_DEPTH=1) so they cannot launder unapproved taps. `done` is recorded like any call (provider otherwise sees unanswered call).
- Approvals: precedence = Hooks rule (allow/ask/deny) > mode (AUTO / RISKY default / EVERYTHING) > prompt. Prompt shown 3 ways at once (chat card, TYPE_APPLICATION_OVERLAY card, notification), any can answer; 3-min timeout => refused + "stop and call done"; cancel settles the card. "Always" writes `allow <tool> in <pkg>` rule. RISKY = MCP tool, SENSITIVE_PACKAGE regex (bank/pay/wallet/password…), or RISKY_WORDS regex in the detail (send/pay/delete/post/call/accept/agree… — many false positives by design). Detail is humanised ("tap \"Send\" in com.x") using describeNode(label) not "node 17".
- Hooks DSL: `allow|ask|deny <tool-glob> [in <pkg-glob>] [matching <regex>]`, first match wins, persisted to files/hooks.txt. User regex unbounded (ReDoS possible).
- Router (cheap/strong model): strong at step 0, planning, after failure ("recovering"), after user steering; cheap otherwise iff previous step's calls were all in MECHANICAL set. README claims $0.07 -> $0.016 same task (vendor claim, UNVERIFIED).
- Compactor: estimate chars/4 (+900/image); soft limit 0.6*contextLimit(default 128k, user-set); stage 1 elide old tool-result bodies to 400 chars + drop old screenshots (keeps last 6 turns); stage 2 summarise "middle" blocks via fast model (<200 words) keeping first block (task) and last 4 blocks; whole blocks only; fold summary into first user turn to avoid two user turns in a row. Dropped content still on disk -> session_search/session_read.
- Projection: chat = append-only event log (SessionEvent) -> two derived views (UI entries, provider messages). Unanswered tool-call blocks (killed run) are DROPPED at replay; trim keeps whole blocks and always re-opens with the original task. "unsettled()" finds asks/plans/tool calls without outcomes after a process kill; chat metadata has an in-flight flag -> "resume" offer.
- LLM backend: ONE OpenAI-compatible chat-completions client (default OpenRouter), SSE streaming, accumulates streamed tool_call deltas, usage+cost (OpenRouter `usage.include`), reasoning on/default/off distinction, echoes provider `reasoning_details` back, images only on user role (screenshot rides as follow-up user message; tool msg has placeholder), keeps only 2 latest screenshots. Retry: RETRYABLE {408,409,425,429,500,502,503,504,520,522,524}, 3 retries, 1s<<attempt, Retry-After capped 30s; no retry on 4xx others; stream drop with nothing received => retry; stream drop AFTER partial output => KEEPS partial (ClosePaw instead FailAndStops — ClosePaw's rule is safer for tool calls). max_tokens fixed 4096. OkHttp: connect 20s, read 120s, NO call timeout. API key in EncryptedSharedPreferences (AES256_GCM/SIV). Stop cancels the HTTP call (invokeOnCompletion{call.cancel()}).
- Lua scripting (luaj, in-process): sandbox = Base+Package(needed for loaded table)+String+Table+Math only; forbids dofile/loadfile/load/loadstring/collectgarbage/debug/require/package/module; no os/io/coroutine/luajava; no LoadState (no bytecode loading). Budget via DebugLib.onInstruction hook: 4,000,000 instructions, 120 mutating actions, 500 calls, 90 s, 20,000 chars source; `Halted : Error` (not Exception) so pcall cannot swallow the budget; cancellation converted to Halted; every phone.* call goes through ScriptHost.tool => ToolPipeline => approvals/record. Prelude (Lua): holds()/all/find/waitFor/ensure(toggle). Saved scripts: compile-checked at save, named, with declared params -> form UI; "Running one yourself costs nothing: no model in it".
  * Relevance: AutoHost ALREADY has Flow (declarative) + QuickJS runtimes with the same broker-gating property; Lua adds nothing. Transferable ideas: (1) instruction/action/call/time budgets that a script cannot catch (check AutoHost QuickJsEngineFactory interrupt handler + flow step budgets for the same property), (2) `ensure(toggle)` helper semantic, (3) saved automation with declared params => form (AutoHost has config_schema -> form), (4) log-as-the-only-account-of-what-happened-while-model-away.
- ControlService (a11y): snapshot walks `windows` (IME+overlays included), excludes own overlay window by root view id, MAX_NODES 300, depth 60, invalidates snapshot on TYPE_WINDOW_STATE_CHANGED (stale node index fails loudly), foreground package from window-state events ignoring own pkg/systemui/android/IME pkgs; `screenProblem()` refuses actions when screen off / keyguard locked; tapNode = refresh() then ACTION_CLICK on first clickable ancestor within 5 hops else coordinate gesture at node centre; gestures AWAITED via GestureResultCallback (onCompleted/onCancelled) with fixed 60 ms tap; typeText = ACTION_SET_TEXT, returns "Typed" if performAction true (NO verification, no refresh-then-compare); password detection (isPassword) hides detail from transcript/approval/log; takeScreenshot throttle 1 s; hardware buffer copied then closed (leak breaks later captures); scope re-created on reconnect; onUnbind only clears shared state if `instance === this` (two instances overlap).
- Overlay: TYPE_APPLICATION_OVERLAY pill + ask card with FLAG_SECURE (claims this excludes the indicator from takeScreenshot; "removing the window per-capture does not work - cached frame") + importantForAccessibility=NO_HIDE_DESCENDANTS. - MCP client (Streamable HTTP, protocol 2025-06-18, bearer or none, no OAuth/stdio, <=200 tools, 90 s read): all MCP tools are treated as "risky" (ask) because they act off-device. Tool names prefixed `mcp__<server>__<tool>`.
- Skills/"playbooks": per-app markdown; only name+description in prompt; `skill` tool loads body; auto-loaded by foreground package/task keywords. Memory: `remember/forget` notes injected in system prompt (privacy: sent to provider).
- Manifest: INTERNET, POST_NOTIFICATIONS, FOREGROUND_SERVICE(+SPECIAL_USE w/ justification property), SYSTEM_ALERT_WINDOW; `allowBackup=false`; activity exported (SEND / PROCESS_TEXT / ASSIST intent filters); QS tile; NO foreground service claimed needed because a11y service is persistent (but they still run RunService FGS 'specialUse' for the notification+stop). network_security_config: **cleartext allowed globally** (base-config) so LAN/llama.cpp endpoints work; warning only in settings UI => AutoHost must NOT copy; use per-domain/LAN-only + UI consent.

## Weaknesses / things NOT to copy
1. No run caps (above). 2. Cleartext globally permitted. 3. typeText unverified. 4. Streamed partial tool call kept after a mid-stream drop (risk of executing a truncated call; truncated JSON args become emptyMap and tool reports missing arg — benign in practice but not by design). 5. RISKY_WORDS regex is English-only and fuzzy. 6. Hooks regex unbounded. 7. `failed()` detection by English substrings ("Failed", "needs"…) is brittle. 8. Memory notes go to the provider. 9. Screenshot FLAG_SECURE trick unverified. 10. Single-module app, singletons (`object Approvals`, `object Chats`) — global state, hard to test; AutoHost's DI is better.
