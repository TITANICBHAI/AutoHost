## Lessons
- **Read both sides of every hand-off; a fake shaped like the caller's wish proves nothing.** A2 to A8 were seven bugs in a row, each hidden by a test double that returned or accepted the shape the agent's code wanted. For each seam: find what the real provider replies or accepts, build the test input from that, and grep for the exact names the code reads (`button` vs `choice`, `ok`, `ref`, a Boolean vs a word, a list vs a text).
- **Give each seam at least one test with the production's own inputs, not the convenient ones.** A13 hid behind a fake clock that read 1 000 ms while the real one reads about 1.76 trillion; a real clock and a real socket (A11) is the cheapest way to see a seam whole. The `app` module's tests compile against the Android platform only, so there is no `com.sun.net.httpserver` there: use `ServerSocket`.
- **Also read what the provider requires back, and compare the timeouts.** A10 came from the vendor's own guide (a value the service hands out and wants returned) and A9 from two waits (300 s prompt, 180 s idle watchdog) that nobody had put side by side. Neither shows up in a test that only checks our own shapes.
- **Test what the provider receives, not only our own form of it.** `ToolCatalogTest` checked a correct `wireSpecs()` while the loop sent `specs()`, which was something else (A1). When a value is turned into JSON for an outside service, a test should read the object that goes into the request.
- A red digest with `0 failing tests` and a module with no results: read `details.md` first. Runs 59 and 80 were an HTTP 429 from Maven Central, not code; do not change code for it (the total tells which module is missing: run 80 ran 1303 tests, and 1303 + 568 for `app` is the 1871 expected). A red digest that names one UI test after a docs-only commit (run 68) is a hint to re-run once before changing code; the second failure of the same test is the signal.
- **A hung test step: read a thread dump, do not guess from timings.** Two wrong theories (a time budget, then memory) cost four CI runs; the dump named the place in one. First check how long a normal run takes (5 to 6 minutes here).
- **Room's default executor is four threads for the whole process**, and under the Compose test rule a `LaunchedEffect` carries on on the thread that finished its last suspend call. A `runBlocking` helper called there can pin a Room thread on a call that needs another. Wrap such calls in `withContext(graph.dispatchers.io)`.
- **A touch at a node's centre misses silently when the node is partly scrolled out of its panel** (runs 40 and 53). Click rows inside scrolling panels by their own click action (`clickByAction`), and let a wait say what is on screen when it fails (`waitForTextOrSay`).
- Read `details.md` on the `ci-results` branch before touching code; fetch with `git fetch -q origin ci-results:refs/remotes/origin/ci-results`. It carries no stack traces and lists failing tests only, so a test timeout is a hypothesis until it passes. **Make a failing UI test name its own step** (`at()` in the journey tests) and split a long journey into small tests.
- A negative check ("Back did not close the app") needs a control that shows it can fail. `onBackPressedDispatcher.onBackPressed()` then `isFinishing` works under Robolectric.
- When a screen moves out of a tab, read the navigation code: `NavStack.TABS` still listed retired tabs and nothing failed until a test pressed Back on them.
- Run `python3 -m pytest tests` before pushing: the architecture ratchet caught a test that seeds run records (`runStore.create(`); a test-only exception needs a dated entry in `KNOWN`, not a renamed variable.
- Lazy-list keys must be unique within one list: namespace them by kind (`ListKeys`, `ChatRow.key`). An activity-only smoke test never lays out screens; compose the real screen in a test.
- After adding a variant to an enum or sealed type, grep every `when` over it (CI run 30). Missing imports (`dp`, `rememberSaveable`) are the usual first CI failure on Compose files.
- `performClick` taps a node's centre: scroll the node fully into view first, and keep the test window taller than the page. A disabled button has no click action: look for it by text only. `SectionHeader` shows its text in capitals, so wait for "VALUES IT CAN BE GIVEN".
- Most "failures" after compile errors were wrong tests, but four were real product bugs: decide by reading the code. A completeness test against the contract caught a missing capability (`device.intent`): generate UI from data, test the join.
- A negative test that greps copy ("no computer") must forbid asking, not mentioning. The flow format lives in five places (parser, executor, Python reference, schema, vectors): change them in one commit and regenerate the vectors.
- Keep LF/CRLF as found; use exact find/replace and re-read.
